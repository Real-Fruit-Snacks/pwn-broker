pwn-broker

Keeps a box's targets, notes, creds and tools in order

I launch it when I start a Hack The Box machine. It asks a few questions, builds the workspace, opens my notes in vim, and stays open as a prompt for the whole session. When the box is done it packs everything into one archive. It is for Kali Linux with a desktop session. One whole box has run in the official Kali image in CI, as root; a real Kali desktop has not: see tested on.

Install, once a release exists

curl -fsSL https://github.com/Real-Fruit-Snacks/pwn-broker/releases/latest/download/install.sh | sh

No release has been published yet, so that line does not work until v0.1.0 is tagged. For a release file already on the machine:

sh install.sh --from pwn-broker-0.1.0-linux-x86_64.tar.gz

To install from a checkout, build a release file first, on x86_64 Linux. The build downloads the pinned inputs and refuses any that does not match its size or SHA-256:

git clone https://github.com/Real-Fruit-Snacks/pwn-broker.git
cd pwn-broker
python3 -m venv .venv && .venv/bin/pip install -e . && .venv/bin/python release/build.py
sh install.sh --from dist/pwn-broker-0.1.0-linux-x86_64.tar.gz

Run it as the user who will use pwn-broker, not with sudo; it asks for sudo itself, once, if it has to create /opt/pwn-broker. A release is one file of about 47 MB that holds its own Python 3.13.18, the app's wheels pinned by SHA-256 and asciinema 3.2.1. The installer unpacks that Python into /opt/pwn-broker/python/, builds the virtual environment in app/ from the wheels, runs setup, and adds /opt/pwn-broker/bin to PATH in ~/.zshrc. It needs sh, tar, gzip and sha256sum, and curl without --from; it needs no python3 and contacts neither PyPI nor asciinema's releases. Nothing goes into the system Python. It takes about 100 MB more on disk, and the app's Python and OpenSSL are fixed when a release is made, not when Kali updates. x86_64 with glibc only. Run it again to upgrade; it replaces python/ and app/ and nothing else, and a failed or interrupted install puts the previous one back. Downloaded, the release file is checked against SHA256SUMS.txt, which comes from the same release: that catches corruption, not a replaced release. With --from it prints the file's SHA-256 to compare with the release page. --from takes a release file only. What still reaches out: an install without --from fetches the release file and its checksum from this repository's release; tool install fetches packages and the index from pwn-shop's releases, or reads a folder; launch asks this repository's releases whether a newer one exists, which check_updates = false turns off. If asciinema is missing or does not match its pin, setup fails and so does the installer; at launch the asciinema check warns and says to run the installer again, and nothing is downloaded.

What it does

A folder per box, and per target

A box lives in ~/pwn-broker/active/<date>_<platform>_<name>/. Each target gets its own folder with creds/, files/, loot/, scans/, exploits/, screenshots/ and recordings/.

A prompt for the whole session

It stays open as forest/dc01 >, with commands for targets, hostnames, credentials, flags, files, recordings, the VPN and status. help lists them. Only one box is open at a time.

Credentials kept as typed

One credential list for the whole box, in creds.toml, each answer stored exactly as typed. The lists/ folder is rebuilt from it, so other tools can read usernames.txt, userpass.txt, hashes.txt or hosts.txt as they are.

The note window

A second terminal runs vim on notes.md with its own vimrc; your ~/.vimrc is never read. It saves when you leave the window and reloads when you come back.

Finish, export, import

finish archives the box and closes it. export writes a snapshot and keeps working. Both write to ~/pwn-broker/wrapped/, and pwn-broker import <file> unpacks one.

Tools, installed and taken off again

tool install <name> installs a package from the index: size and SHA-256 checked, no install script, and a Python tool gets its own virtual environment from bundled wheels with no network. Kali's own copies are never touched. A tool that needs root is run as sudo <full path>, which the app prints: a bare sudo finds nothing, or Kali's own command of that name, as with the ligolo-proxy that Kali's ligolo-ng installs. finish removes the box's tools unless another unfinished box still uses them. The app can also install a Python tool that brings its own Python as a shared runtime package, such as python-3.13, installed with the first tool that requires it and removed with the last; it puts nothing on PATH, so Kali's python3 is never shadowed. Build 3 of certipy and targetedkerberoast does this and is the only published build of each; builds 1 and 2 were withdrawn on 2026-11-15, before any box had used them. tool history lists every tool the box has had, removed ones too, and ~/pwn-broker/tools.log records each install and removal across boxes. The first set of packages is x86_64 only. A tool's data in the home folder is the one thing removed outside /opt/pwn-broker, at finish or when the last box that uses the tool removes it, and only if it did not exist before the install. It is copied into the box first, and a path that could not be copied in full is kept, with a warning.

Recording a window

record [target], typed in any terminal while a box is open, records that window under a pinned asciinema 3.2.1 into the target's recordings/ folder, with [rec dc01] in front of the zsh or bash prompt. Beside each .cast the app writes a .txt with the time on every line of text, for grep. replay lists and plays them. Keystrokes are not recorded, but a password typed on a command line is.

/etc/hosts and the VPN

A target with an IP and a hostname can have one line in /etc/hosts, marked with the box ID; host add adds names to it and finish takes it out. Lines that are not the app's are never changed. vpn start copies a .ovpn file into the box and starts OpenVPN in the background; the file is never archived, and vpn stop stops only the process the app started. Each new target with an IP is pinged once.

The note

notes.md starts with a box drawn in # that holds the box details and one row per target. The app redraws it whenever the targets change.

Below it, each target has a section wrapped in a vim fold that starts with its Target: line, and the note opens with every fold closed down to that line. F8 adds an empty fold below the cursor.

IP addresses are Amber and <Placeholder> text is Ember wherever they appear. The app changes nothing else in the note, apart from a Target: line it wrote when that target is renamed or edited.

Tested on

  • Not tested: a real Kali desktop session and its terminal. The Kali run used a virtual display and xterm, so the window manager, focus and the terminal Kali opens by default have not been tried. Nor has your own VM.
  • Not tested: a normal user. The Kali run is root, so sudo for /etc/hosts and OpenVPN has not run, and neither has the installer's own sudo step.
  • Not tested: a real Hack The Box connection. The OpenVPN file in the Kali run has no server behind it.
  • Not tested: a real tool package used by hand. pwn-shop's CI installed and started each one (kerbrute, pspy, certipy, targetedkerberoast, ligolo-ng, peass-ng) on Kali, in a container. None has been run on a Kali desktop, against a real target, or by a normal user with sudo.

Known issues

  • The recording, /etc/hosts, VPN and ping part has run on Kali only as root, in a container, with a virtual display and an OpenVPN file with no server. The checks still to run by hand are in docs/kali-checks.md.
  • Builds 1 and 2 of the two Python tool packages, certipy and targetedkerberoast, were withdrawn on 2026-11-15, before any box had used them. Build 3 of each, which requires the python-3.13 runtime, is the only one published. The other four tools need no Python.
  • After finish removes the working folder, the note window stays open on a file that no longer exists. Close it by hand.
  • A window still recording has no text copy until it closes or the box is exported. A full-screen program appears only in the .cast.
  • A password typed on a command line in a recorded window is recorded, and goes into the archive. The [rec] prefix is for zsh and bash only.
  • finish refuses while a window is recording for the box. quit leaves the box's /etc/hosts lines in place; only finish removes them.
  • Only tun interfaces count as a VPN. Only OpenVPN files can be started, one VPN at a time, and an archive holds no copy of the VPN file. A tunnel the app did not start is never stopped by it.
  • Ctrl-C while vpn start waits for OpenVPN to write its process ID can leave an OpenVPN running that the app does not track; stop it by hand. Starting a second tunnel while one the app did not start is up is reported as not up after 15 seconds, because the app reads only the lowest-numbered tunnel.
  • Lines in /etc/hosts that are not the app's are never changed, so one that names the same host with another address has to be removed by hand.
  • tool install from the published index has not been run on Kali. CI installs every package from a folder, with the network off. From the published address, the app's own download code has fetched the index and two packages (certipy build 3 and the python-3.13 runtime) and checked each against the index, on Windows.
  • No release has been published, so the curl install line does not work until v0.1.0 is tagged. To install now, build a release file from a checkout, as above.
  • The app's own Python and OpenSSL are fixed when a release is made, not when Kali updates, and the app takes about 100 MB more on disk. A release is x86_64 with glibc only. After a killed or interrupted install, /opt/pwn-broker/.install.<random> can be left behind, and it may hold the previous install.
  • cred list marks a secret it cannot show exactly (a tab, another control character, or a space at either end) with * after the number. cred show prints it unchanged.
  • Links and special files (named pipes, sockets, devices) in a box are not archived. export and finish list them, and finish says how many will go when the folder is removed.
