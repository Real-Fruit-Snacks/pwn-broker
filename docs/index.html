pwn-broker

Keeps a box's targets, notes, creds and tools in order

I launch it when I start a Hack The Box machine. It asks a few questions, builds the workspace, opens my notes in vim, and stays open as a prompt for the whole session. When the box is done it packs everything into one archive. It is for Kali Linux with a desktop session, and it has not been run on Kali yet: see tested on.

Install, once a release exists

curl -fsSL https://raw.githubusercontent.com/Real-Fruit-Snacks/pwn-broker/main/install.sh | sh

No release has been published yet, so that line does not work today. From a clone:

git clone https://github.com/Real-Fruit-Snacks/pwn-broker.git
cd pwn-broker
sh install.sh --from .

Run it as the user who will use pwn-broker, not with sudo; it asks for sudo itself, once, if it has to create /opt/pwn-broker. It builds a virtual environment there and adds /opt/pwn-broker/bin to PATH in ~/.zshrc. Nothing goes into the system Python. Run it again to upgrade.

What it does

A folder per box, and per target

A box lives in ~/pwn-broker/active/<date>_<platform>_<name>/. Each target gets its own folder with creds/, files/, loot/, scans/, exploits/, screenshots/ and recordings/.

A prompt for the whole session

It stays open as forest/dc01 >, with commands for targets, credentials, flags, files and status. help lists them. Only one box is open at a time.

Credentials kept as typed

One credential list for the whole box, in creds.toml, each answer stored exactly as typed. The lists/ folder is rebuilt from it, so other tools can read usernames.txt, userpass.txt, hashes.txt or hosts.txt as they are.

The note window

A second terminal runs vim on notes.md with its own vimrc; your ~/.vimrc is never read. It saves when you leave the window and reloads when you come back.

Finish, export, import

finish archives the box and closes it. export writes a snapshot and keeps working. Both write to ~/pwn-broker/wrapped/, and pwn-broker import <file> unpacks one.

Tools, installed and taken off again

tool install <name> installs a package from the index: size and SHA-256 checked, no install script, and a Python tool gets its own virtual environment from bundled wheels with no network. Kali's own copies are never touched. A tool that needs root is run as sudo <full path>, which the app prints. finish removes the box's tools unless another unfinished box still uses them. The first set of packages is x86_64 only. A tool's data in the home folder is the one thing removed outside /opt/pwn-broker, at finish only, and only if it did not exist before the install.

The note

notes.md starts with a box drawn in # that holds the box details and one row per target. The app redraws it whenever the targets change.

Below it, each target has a section wrapped in a vim fold that starts with its Target: line, and the note opens with every fold closed down to that line. F8 adds an empty fold below the cursor.

IP addresses are Amber and <Placeholder> text is Ember wherever they appear. The app changes nothing else in the note, apart from a Target: line it wrote when that target is renamed or edited.

Tested on

  • Not tested: Kali Linux. The app has not been run there, and the checks in docs/kali-checks.md, the tool checks included, have not been run yet.
  • Not tested: any real tool package. None of the six planned for pwn-shop (kerbrute, pspy, certipy, targetedkerberoast, ligolo-ng, peass-ng) has been installed on Kali.
  • Not tested: the installer's download. No release exists, so fetching the wheel and checking its SHA-256 has not run.
  • Not tested: the note window and the prompt on a real terminal.
  • The unit tests, on Windows 11 with Python 3.13: 1264 passed, 33 skipped, with warnings treated as errors. The skips are the tests that need Linux (symlinks, named pipes, file modes, ownership, backslash file names, the installer, virtual environments and launchers).
  • The unit tests, on Ubuntu 24.04 in CI with Python 3.11, 3.12 and 3.13: on Linux they include real tool installs into a virtual environment and the launchers. No Linux count is given here, because none has been recorded for this version.
  • install.sh, run twice from a checkout on Ubuntu 24.04 in CI: the first run builds the environment, installs the package and writes the launcher and the PATH line; the second reuses the environment and adds no second PATH line.
  • The vimrc, run by Vim 9.2 in headless mode on a note the app wrote: folds, fold text, F8, colours, settings, and the reload after the app changes the note. Timers and focus events do not fire in that mode, so the tests run the check by hand.

Known issues

  • Recording is not in this release. It is a later phase in the design.
  • The published tool index is private for now, because pwn-shop is. Until it is public, tools_index must point at a folder that holds index.toml and the zips it names. The first one to try needs pwn-shop to exist, and it does not yet.
  • No release has been published, so the curl install line does not work yet. Install from a clone.
  • cred list marks a secret it cannot show exactly (a tab, another control character, or a space at either end) with * after the number. cred show prints it unchanged.
  • Links and special files (named pipes, sockets, devices) in a box are not archived. export and finish list them, and finish says how many will go when the folder is removed.
