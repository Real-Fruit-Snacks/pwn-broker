pwn-broker

Keeps a box's targets, notes, creds and tools in order

I launch it when I start a Hack The Box machine. It asks a few questions, builds the workspace, opens my notes in vim, and stays open as a prompt for the whole session. When the box is done it packs everything into one archive.

  1. InstallRun once
    curl -fsSL https://github.com/Real-Fruit-Snacks/pwn-broker/releases/latest/download/install.sh | sh

    As the user who will use pwn-broker, not with sudo. It downloads one release file, checks its SHA-256, and puts the app and its own Python in /opt/pwn-broker. Run it again to upgrade.

What it does

  • A folder per boxactive/

    A box lives in ~/pwn-broker/active/<date>_<platform>_<name>/. Each target gets its own folder with creds/, files/, loot/, scans/, exploits/, screenshots/ and recordings/. A second box with the same name and platform on the same day gets -2, so one box's archive is never offered to another for replacing.

  • A prompt for the sessionforest/dc01 >

    Commands for targets, hostnames, credentials, flags, files, recordings, the VPN and status. help lists them; exit leaves as quit does. A yes or no question takes y, yes, n, no or Enter for its default; a wrong argument gets the command's usage under the fail line. One box is open at a time.

  • Credentials as typedcreds.toml

    One credential list for the whole box, each answer stored exactly as typed. The lists/ folder is rebuilt from it, so other tools can read usernames.txt, userpass.txt, hashes.txt or hosts.txt as they are.

  • The note windownotes.md

    A second terminal runs vim on the note with its own vimrc; your ~/.vimrc is never read. It saves when you leave the window and reloads when you come back, and finish closes it. It keeps the folder, with a warn line, when the note has unsaved changes or changed since the archive was made.

  • Finish, export, importwrapped/

    finish archives the box and closes it. export writes a snapshot and keeps working. Both write to ~/pwn-broker/wrapped/, and pwn-broker import <file> unpacks one.

  • /etc/hosts and the VPNvpn start

    A target with an IP and a hostname can have one line in /etc/hosts, marked with the box ID; host add adds names and finish takes it out. Lines that are not the app's are never changed. vpn start copies a .ovpn file into the box and starts OpenVPN in the background; the file is never archived, and vpn stop stops only the process the app started. Each new target with an IP is pinged once.

  • Scans in the backgroundscan

    nmap against the current target: the top 1,000 ports first, then every TCP port with scripts on only the ones it found, with -oA output in the target's scans/. A line in the prompt says when each is done and which ports are open. scan udp takes the top 100 UDP ports as root, and finish waits while a scan runs.

  • Files served to the targetserve

    The target's upload/ folder and the tools' files over HTTP on the tunnel's address, behind a random path, with nothing listed. serve files prints the iwr or wget line for each file, and a PUT back saves a file into loot/, never over one already there. It runs until serve stop or finish.

  • Search across the boxsearch

    Text in the current target's files, the text copies of its recordings and its section of the note, or with search all the whole box, credential lists included. Binary files and the VPN folder are skipped, and so is a playbook's text until you fill it in.

  • Tools, on and off againtool install

    A package from pwn-shop's index, with its size and SHA-256 checked and no install script: NetExec, Impacket, Certipy, Rubeus and the BloodHound collectors, PEASS-ng and pspy, the potatoes, ligolo-ng and chisel, and the rest of its list. The Python ones bring their own Python as a shared runtime that puts nothing on PATH. finish takes them off unless another unfinished box still uses them, and tool history lists every tool the box has had.

  • Playbooks in the note:Pb

    tool install playbooks gets pwn-playbooks, short notes for one job each. :Pb <name> in the note window reads one in below the cursor, Tab completing the name from any part of it, and its few lines of vim fill in its <Placeholder> values in that playbook and nowhere else. At the prompt, playbook list lists them by folder and title and playbook show <name> prints one. The first new box on a machine asks whether new boxes should get them, and keeps the answer.

  • A report at finishtool install report

    With pwn-report in the box, finish builds a private report beside the finished archive: report.md with the box, its targets and flags, a timeline from the archive's own records and an index of the evidence, each file with its SHA-256, and a copy of the scans, screenshots and exploits, linked from it. A report that fails is a warning and finish goes on; one is never replaced. New boxes can get the tool after one question, as they get the playbooks.

  • Recording a windowrecord

    Typed in any terminal while a box is open, it records that window under a pinned asciinema 3.2.1 into the target's recordings/, with [rec dc01] in front of the prompt. Beside each .cast goes a .txt with the time on every line, for grep; replay plays them. Keystrokes are not recorded, but a password typed on a command line is.

The note

notes.md starts with a box drawn in # that holds the box details and one row per target; the app redraws it whenever the targets change. Each target has a section in a vim fold that starts with its Target: line, and the note opens with every fold closed down to that line.

  • New foldF8
  • Target's IP,i
  • A credential,c
  • Date and time,t
  • Tick a box,x
  • List the keys,h
  • Read a playbook in:Pb <name>

IP addresses are amber and <Placeholder> text is orange wherever they appear. The app changes nothing else in the note, apart from a Target: line it wrote when that target is renamed or edited. Here dc01's fold is open and ws01's closed; the two lines under enumeration are mine.

Known issues

  • x86_64 Linux with glibc only. On any other machine the installer stops and says so.
  • The app's Python and its OpenSSL are as new as the release, not as Kali; a fix to them reaches you only in a new release. They take about 100 MB more on disk.
  • Close pwn-broker before you upgrade. The installer replaces app/ and python/ under a running prompt, and does not check.
  • On a terminal that hosts all its windows in one process, such as gnome-terminal, finish closes the note's vim but cannot close its window.
  • Nothing is signed. SHA256SUMS.txt comes from the same release as the file it checks, and the tool index every zip is checked against is not signed either: the checks catch a corrupted download or a swapped zip, not who published them.
  • A password typed on a command line in a recorded window is in the recording and the archive. One typed at a hidden prompt is not.
  • quit leaves the box's /etc/hosts lines in place; only finish removes them.
  • finish refuses while a window is recording for the box or one of its tools is running. Exit those first.
