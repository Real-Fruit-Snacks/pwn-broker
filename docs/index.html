pwn-broker

Keeps a box's targets, notes, creds and tools in order

I launch it when I start a Hack The Box machine. It asks a few questions, builds the workspace, opens my notes in vim, and stays open as a prompt for the whole session. When the box is done it packs everything into one archive. It is for Kali Linux with a desktop session; see what it has been tested on.

Install

curl -fsSL https://github.com/Real-Fruit-Snacks/pwn-broker/releases/latest/download/install.sh | sh

No network on the Kali machine: copy the release file and install.sh from the latest release across and run this. It prints the file's SHA-256 to compare with the release page, and contacts nothing.

sh install.sh --from pwn-broker-0.1.0-linux-x86_64.tar.gz

Run it as the user who will use pwn-broker, not with sudo. It downloads one release file, checks its SHA-256, and puts the app and its own Python in /opt/pwn-broker; it needs no Python from the machine. x86_64 Linux with glibc only. Run it again to upgrade. The guide has the options and what the install trusts.

What it does

A folder per box, and per target

A box lives in ~/pwn-broker/active/<date>_<platform>_<name>/. Each target gets its own folder with creds/, files/, loot/, scans/, exploits/, screenshots/ and recordings/. A second box with the same name and platform on the same day gets -2 on its folder and its archives, so one box's archive is never offered to another for replacing.

A prompt for the whole session

It stays open as forest/dc01 >, with commands for targets, hostnames, credentials, flags, files, recordings, the VPN and status. help lists them; exit leaves as quit does, and clear clears the screen. A yes or no question takes y, yes, n, no, or Enter for its default, and asks again after anything else; a wrong argument gets the command's usage under the fail line. Only one box is open at a time.

Credentials kept as typed

One credential list for the whole box, in creds.toml, each answer stored exactly as typed. The lists/ folder is rebuilt from it, so other tools can read usernames.txt, userpass.txt, hashes.txt or hosts.txt as they are.

The note window

A second terminal runs vim on notes.md with its own vimrc; your ~/.vimrc is never read. It saves when you leave the window and reloads when you come back. A box has one note window: opening the box again while it is open says ok the note is already open, and finish closes it when it removes the working folder. It keeps the folder, with a warn line, when the note has unsaved changes or has changed since the archive was made.

Finish, export, import

finish archives the box and closes it. export writes a snapshot and keeps working. Both write to ~/pwn-broker/wrapped/, and pwn-broker import <file> unpacks one.

Tools, installed and taken off again

tool install <name> installs a package from pwn-shop's index, with its size and SHA-256 checked and no install script: kerbrute, pspy, certipy, targetedkerberoast, ligolo-ng and peass-ng. The Python ones bring their own Python as a shared runtime that puts nothing on PATH, so Kali's python3 is never used or shadowed. finish takes the box's tools off again unless another unfinished box still uses them, and tool history lists every tool the box has had.

Recording a window

record [target], typed in any terminal while a box is open, records that window under a pinned asciinema 3.2.1 into the target's recordings/ folder, with [rec dc01] in front of the zsh or bash prompt. Beside each .cast the app writes a .txt with the time on every line of text, for grep. replay lists and plays them. Keystrokes are not recorded, but a password typed on a command line is.

/etc/hosts and the VPN

A target with an IP and a hostname can have one line in /etc/hosts, marked with the box ID; host add adds names to it and finish takes it out. Lines that are not the app's are never changed. vpn start copies a .ovpn file into the box and starts OpenVPN in the background; the file is never archived, and vpn stop stops only the process the app started. Each new target with an IP is pinged once.

The note

notes.md starts with a box drawn in # that holds the box details and one row per target. The app redraws it whenever the targets change.

Below it, each target has a section wrapped in a vim fold that starts with its Target: line, and the note opens with every fold closed down to that line. F8 adds an empty fold below the cursor.

IP addresses are Amber and <Placeholder> text is Ember wherever they appear. The app changes nothing else in the note, apart from a Target: line it wrote when that target is renamed or edited.

Tested on

  • Not tested: a full Kali desktop session. CI used a virtual display and xterm, and the run by hand Kali's qterminal under WSL.
  • Not tested: a real Hack The Box connection. The OpenVPN file in the Kali run has no server behind it.
  • The unit suite on Windows 11 under Python 3.13, and on Ubuntu 24.04 in CI under Python 3.11, 3.12, 3.13 and 3.14 and once more as root, with warnings treated as errors.
  • One whole box in the official Kali image in CI (Kali 2026.3, as root): installed from the release file with the container's network off, then new box to finish and import, with a real OpenVPN and tun0, under a virtual display with xterm.
  • An install in a bare debian:stable-slim container with no Python and no network.
  • Every command by hand in Kali 2026.2 under WSL 2, as root, with Kali's own qterminal, including building the release file there and upgrading an install made by the old installer.
  • The published v0.1.0 there too: the install line above, then a box with all six tools installed from the published index, each started once, and taken off again by finish.
  • And once more as a normal user whose sudo asks for a password: the install line, then a box with /etc/hosts, the VPN, three tools, a recording, files made with sudo and finish.
  • The full record, with counts, versions and dates, is in docs/tested.md.

Known issues

  • x86_64 Linux with glibc only. On any other machine the installer stops and says so.
  • The app's Python and its OpenSSL are as new as the release, not as Kali; a fix to them reaches you only in a new release. They take about 100 MB more on disk.
  • Close pwn-broker before you upgrade. The installer replaces app/ and python/ under a running prompt, and does not check.
  • On a terminal that hosts all its windows in one process, such as gnome-terminal, finish closes the note's vim but cannot close its window.
  • Nothing is signed. SHA256SUMS.txt comes from the same release as the file it checks, and the tool index that every zip is checked against is not signed either: the checks catch a corrupted download or a swapped zip, not who published them.
  • A password typed on a command line in a recorded window is in the recording and the archive. One typed at a hidden prompt is not.
  • quit leaves the box's /etc/hosts lines in place; only finish removes them.
  • finish refuses while a window is recording for the box or one of its tools is running. Exit those first.
