# Security

## Supported versions

The latest release only. Fixes ship as a new SemVer tag; there are no backports.

## Reporting

Use GitHub's private vulnerability reporting on this repository (Security → Report a vulnerability). Don't open a public issue for anything that could write outside a box folder or expose a credential.

Include `pwn-broker --version`, your Kali and Python versions, whether you ran it as root or a normal user, and the commands that show the problem. Use placeholder credentials and flags.

This is a one-person project. I read reports within a week. If it's real, the fix and the changelog entry name the problem plainly.

## What counts

- An imported archive that writes, links or overwrites anything outside the box folder it is unpacked into.
- Anything that alters, leaks or mis-stores a credential: a value changed on the way in or out or a secret written somewhere it shouldn't be.
- The installer or its checksum step: `install.sh` installing a wheel whose SHA-256 does not match `SHA256SUMS.txt`, or deleting or replacing something that isn't its own.
- A tool package or index that gets past the checks: a download or cached zip used although its size or SHA-256 differs from the index, a package whose code runs during install (the app itself runs only an interpreter and `pip`: for a tool on a runtime, the runtime's interpreter with `-m venv` and then the new environment's `pip`; for a schema 1 Python tool, Kali's `python3 -c` to read its version, `python3 -m venv`, and then `pip`; `pip` always with the flags listed below), an interpreter or `pip` during an install that reads the caller's `PYTHON*` or `PIP_*` variables, a `pip` configuration file or a module from the caller's working folder, a `wheels.lock` line that reaches pip as anything but an exact pin with hashes, a Python tool installed from anything but its bundled, hash-checked wheels, or an entry that unpacks outside the tool's folder.
- A runtime's archive that writes, links or overwrites anything outside the runtime's folder, or that is partly unpacked and then used: a hard link, device, pipe or sparse file, an absolute name or one with `..`, a backslash, a colon or a control character, a link whose target is absolute or leads outside the folder, directly or through another link, or an archive past 20,000 entries or 1 GiB, that gets through.
- A runtime removed while an installed tool requires it, or a runtime's interpreter placed in `/opt/pwn-broker/bin`.
- The tool log, `~/pwn-broker/tools.log`, readable by anyone but you, or anything in it read back and acted on.
- A tool's folder, launchers or upload files created or removed outside `/opt/pwn-broker`, or tool data deleted from the home folder that existed before the install, that was not copied into the box in full, that is not strictly inside the home folder, that sits behind a link, or that another unfinished box still uses.
- The `sudo` handling: a way to run something as root that the user didn't ask for, or ownership left wrong after a root-run tool.
- `/etc/hosts`: any change to a line the app did not mark with a box ID, or a hostname, address or comment that reaches the file other than as the app's own line.
- The VPN: `vpn stop` signalling a process the app did not start, the VPN file readable by anyone but you, or the file reaching `files.toml`, a manifest or an archive.
- asciinema: `record` or `replay` running an asciinema that does not match the pinned SHA-256, or a recording written anywhere but the box.

## What this tool handles

- Network: none while you work, except the `tool` commands that need the index or a package, which download from `tools_index` when it is a URL; the asciinema download, when the `asciinema` check offers it and you say yes; one ping to each new target's first IP; and OpenVPN, when you start it. It uploads nothing, recordings included. The installer downloads the wheel and `SHA256SUMS.txt` from the latest GitHub release over HTTPS and checks the wheel's SHA-256 before installing anything, then asciinema, unless given `--no-asciinema`. Without asciinema, each launch asks `fix it now? [Y/n]` at the `asciinema` check, and Enter downloads it; answer `n` to keep it off the machine.
- Credentials: kept exactly as typed in a box's own files on your disk, and copied into the `lists/` folder for other tools. They are not encrypted; treat a box folder, its archives and its exports like the credentials they hold. A recording holds whatever the terminal showed, so a password typed on a command line is in it and in the archive.
- Privileges: it runs as the user who installed it and refuses to start as anyone else, and so does `record`. It uses `sudo` only for the few privileged steps it needs, such as creating its install folder, correcting file ownership, writing `/etc/hosts`, and starting and stopping OpenVPN.
- `/etc/hosts`: written directly as root, or as a normal user staged in `/opt/pwn-broker/run` and copied into place with `sudo cp`. Only the lines the app marked with a box ID change; every other line is written back byte for byte, apart from a line break added at the end when the file lacks one, and the file is written in place, so the file's owner and mode stay. Only a plain hostname (letters, digits, hyphens and dots) and a parsed IP address are written, so nothing can add a second entry or a comment. A missing file, a link or anything but a regular file is left alone.
- VPN: OpenVPN is started as root, directly or through `sudo`, from a file you chose. That file's `up` and `down` scripts, if it has any, run as root, as they would if you ran `openvpn` yourself; start only a file you trust. The file is copied into the box's `vpn/` folder with mode 600, and the copy OpenVPN reads is kept in `/opt/pwn-broker/run/vpn/`, also mode 600. The `vpn/` folder never enters `files.toml`, the manifest or an archive; the box records only the file's name and SHA-256. `vpn stop` signals a process only when its ID, start time and name, `openvpn`, all match what the app recorded.
- asciinema: fetched from asciinema's own GitHub release over HTTPS, at install or when the `asciinema` check offers it, and kept only if its size and SHA-256 match the values pinned in the app. `record` and `replay` check that SHA-256 again before each run. It runs with settings folders of the app's own, and writes recordings only to the box.
- Archives: unpacking refuses any entry that would land outside the box folder.
- Tool packages: a download is checked against the size and SHA-256 in the index, and so is a cached zip each time it is used. A package holds no install script, and nothing from a tool's package runs during install; a Python tool's dependencies are installed from wheels in the package with `pip --no-index --only-binary :all: --require-hashes`. Its `wheels.lock` is checked line by line, when the package is unpacked and again right before pip reads it: every line must be `name==version` followed by SHA-256 hashes, so no option, URL, marker or other file reaches pip. Unpacking refuses any entry outside the tool's folder, and any link. Deletes are guarded in two ways. A tool's folder, its launchers and its upload files are created and removed only inside `/opt/pwn-broker`, whatever a manifest or index names. A tool's data in the home folder is the one thing removed outside it, at `finish` or when the last box that uses the tool removes it: a path is deleted only if it did not exist before the install, sits strictly inside the home folder, has no link anywhere on the way to it, and no other unfinished box uses the tool. It is copied into the box first, and a path that could not be copied in full is kept, with a warning. An index or package whose `schema` is not 1 or 2 is refused; schema 2 is only for a runtime and a tool that requires one. The index and the zips come from `tools_index`, over HTTPS or from a folder; the hash check catches corruption and a swapped zip, but the index itself is not signed, so it does not prove who published it. The app can install a Python tool that requires a runtime, as build 3 of `certipy` and `targetedkerberoast` does: a package that carries a CPython build from python-build-standalone byte for byte as a gzip tar, checked like any other zip. The app unpacks that archive itself, not through `tarfile`'s extraction. Every header is read and checked before anything is written, so a damaged or cut-short archive is refused with nothing written, and no more data is decompressed than the entries declare plus a small allowance each. Only regular files, folders and symbolic links are allowed; a name or link target must be relative, stay inside the runtime's folder once every link in the archive is followed, hold no backslash, colon or control character, and be at most 4,096 bytes; at most 20,000 entries and 1 GiB. Files get mode 644 or 755. The archive is unpacked into a temporary folder and renamed into place, so a half-unpacked runtime is never used, and the interpreter it names must be a regular file inside it. During an install the runtime's interpreter makes the tool's virtual environment and that environment's `pip` installs the bundled wheels; nothing else from the runtime runs. The interpreter and `pip`, and Kali's `python3` for a schema 1 tool, run with `-I` (and `pip` with `--isolated`), in the tool's own folder, with every `PYTHON*` and `PIP_*` variable removed and `PIP_CONFIG_FILE` set to the null device. A runtime puts nothing in `/opt/pwn-broker/bin`, and is removed only when no installed tool requires it; while a box folder cannot be read, none is removed. The runtime carries its own OpenSSL and other libraries, which are only as current as the runtime's latest build. `/opt/pwn-broker/bin` is writable by your user and first on your PATH, so anything running as you could place a command there. On a single-user lab VM that is acceptable; it would not be on a shared machine.
- Tool log: `~/pwn-broker/tools.log` holds a line for each tool a box installed or took off, and for each runtime installed or removed with one. Each line holds, in order: the time, the event (`install`, `remove` or `finish`), the box's name and ID, the tool's name with its version and build, and the package's SHA-256, then `runtime` on a runtime's line. It is created with mode 600 and set to 600 again on every write, it is only added to, and the app never reads it back. Control and format characters in a box's name, such as a bidirectional override, are written as `?`.

## Out of scope

The tools you run alongside it, and Hack The Box itself: report to the tool's maintainers and to [Hack The Box](https://help.hackthebox.com/).
